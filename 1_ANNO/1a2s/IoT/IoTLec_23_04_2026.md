# LoRaWAN Technology

End nodes are IoT devices such as: sensors or actuators

Network server: manages join requests, downlinks, data rates and duplicated frames.
It can't decrypt payloads.

Application server: Receives packets from network server. 
Schedules responses for the end nodes and decrypts payloads.

both network and application servers are softwares, they are not hardware components.
Obviosly they can be deployed on different hardwares.

LoRa nodes can have 3 classes based on how the downlinks are managed.

- Class A: every LoRa device should implement the class A

Class B and C have an increasing energy cost

- Class B: messages are allowed in a downlink periodic window. the communication needs to be syncrhonized
- Class C: The devices is constantly in continous listening, except when they are listening

With two Join methods for a LoRa network:
- ABP (Activation by personalization) static option when we need to configure the parameters for connecting to the network. they are stored inside the device.

- OTAA (Over The Air Activation): it's recommend by the specification, the session key are generated for every join (?????? I missed the last part)

Gateways can be divided in two categories:
- Minimal: they cannot work as standalone but they need to be plugged to another device
- GW with an Operating System: they offer more functionalities and they are provided with an OS which makes them more sophisticated.
